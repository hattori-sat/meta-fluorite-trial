## Inferences

- The Flutter/Dart package launch path, parent Wayland surface, native scene
  setup, Vulkan acquire/submit, and Vulkan present completion are not blocked in
  this isolated path.
- The earlier black native region was therefore not explained by QMP capture,
  display resolution alone, or a total Flutter UI failure.
- Production asset/resource/pipeline setup is now the leading differentiator
  between the failing production path and the passing pure fixture path.

## Hypotheses and UNKNOWN

- Leading hypothesis: production asynchronous asset/resource or pipeline work
  starves or blocks the same Filament/driver queue used by the native frame.
- Alternative hypothesis: production light/entity setup or another scene setup
  command triggers a driver/WSI interaction that the fixture avoids.
- UNKNOWN: the exact first production command or resource responsible; the
  production scene and Planetarium comparison on rootfs `0177` remain pending.
- The fixture intentionally skips production light setup, so repeated
  `Light not found` messages are expected diagnostic noise and are not treated
  as proof of a cube-rendering failure.

### Static analysis

- `IndirectLightSystem::onSystemInit()` calls `setDefaultIndirectLight()`,
  which asynchronously posts a Filament `IndirectLight::Builder` operation.
- `RunPostSetupLoad()` can then call `setIndirectLight()` again when the scene
  deserializes a `DefaultIndirectLight`, posting a second builder operation.
- In the same post-setup path, `setUpLoadingModels()` queues every production
  model through the ECS strand. `ModelSystem::updateAsyncAssetLoading()` calls
  `asyncUpdateLoad()` each update and adds model instances to the scene only
  after global progress reaches `1.0`.

### Interpretation

- The individual matrix identifies indirect-light setup as the first strong
  runtime boundary: restoring it prevents present in the model-suppressed
  case, while skipping it restores the self-made cube path.
- Restoring model loading still produces a clear-only frame and later stalls,
  so production object visibility remains unresolved. The evidence supports
  an indirect-light async command and model async-loading interaction, not a
  final fix that simply removes environment lighting.
