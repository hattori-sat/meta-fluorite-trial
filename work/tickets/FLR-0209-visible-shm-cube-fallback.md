## Work unit

Add an opt-in, current-source SHM fallback that draws a clearly three-dimensional
cube into a Wayland child surface while leaving the existing 2D Flutter HUD
visible. This verifies that the compositor and display region can show a
known 3D image, independently of the currently broken native Vulkan WSI RGB
transfer.

## Hypotheses

1. H1: an opt-in `wl_shm` child surface with explicit cube pixels is visible in
   QMP, proving the 2D/3D display and Wayland composition boundary works.
2. H2: the child surface is also black, proving the remaining failure is in
   Wayland surface setup or display-region ownership rather than Vulkan WSI.

## Conclusion

H1 is **PASS**: a deterministic three-face SHM cube and the existing 2D
`Scenes` button are visible in the same QMP-only frame. This proves the
Wayland/compositor/display region can show a known 3D image and that the
previous black native Vulkan frame is not a universal display failure.

The native Vulkan WSI RGB path remains unresolved. The runtime marker reports
`left=460 top=260`, but QMP observes the SHM child at the upper-left
`[0,0,360,280]`. This is a separate child-surface geometry/commit issue and is
opened as FLR-0211; it is not folded into this completed fallback ticket.

### Act

Retain the fallback as a diagnostic proof and continue with FLR-0211 for the
surface-position mismatch and the native WSI RGB path. Do not claim that the
production Vulkan object is fixed yet.
