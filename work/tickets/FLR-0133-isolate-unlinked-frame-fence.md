## Work unit

Explain why the normal Dart Fluorite run reaches Shape readiness and
deserialized-camera application but does not reach a valid ViewTarget draw.
The first observed divergence is an unlinked Vulkan frame fence handled by
Filament's `FrameSkipper`. This ticket is a diagnostic unit: reproduce the
boundary, map the fence lifecycle, and decide whether a source change is
justified. It must not reuse FLR-0132's ticket for a new patch.

## Problem

The current runtime reports `FLR0026_FRAME_FENCE_WAIT_LINKED linked=false`
followed by `FLR0026_FRAME_SKIP_STATUS status=1`. Static source inspection
shows that an unlinked fence is treated as `TIMEOUT_EXPIRED` unless the
diagnostic override is enabled. `Renderer::beginFrame()` delegates to
`FrameSkipper::shouldRenderFrame()`, and `ViewTarget::DrawFrame()` calls
`render(fview_)` only when `beginFrame()` returns true. The reason the fence
has no linked command fence is UNKNOWN.

## Success criteria

- Reproduce the boundary with one authoritative QEMU, one conditional
  `flutter-auto`, bounded runtime traces, and QMP-only evidence.
- Distinguish `NO_FENCE`, linked/satisfied, linked/timeout, and unlinked
  fence states, and correlate them with `beginFrame`, target draw, submit, and
  present markers.
- Identify the owner and lifecycle event that should link the command fence;
  record an explicit UNKNOWN if the evidence does not establish it.
- Treat `FLR0026_TREAT_UNLINKED_FENCE_READY=1` as a diagnostic comparison only;
  it is not a product fix and must not be left as an unexplained workaround.
- If a source change is justified, stop at the evidence boundary and create a
  separate implementation ticket before using Mac Devtool to edit and
  generate a new patch.
- End with a negotiated QMP quit, zero residual QEMU/`flutter-auto` processes,
  and no leftover QMP socket.

## Inferences

- The current first source-owned divergence is between Vulkan fence wait and
  `ViewTarget::DrawFrame()`'s `render(fview_)`, not the Dart camera handoff or
  Shape creation.
- A successful Vulkan submit marker by itself is insufficient evidence of a
  valid 3D ViewTarget frame when target draw/present markers are absent.
- The ready override is a useful discriminator for frame admission, but it is
  not sufficient to produce visible Dart 3D pixels. The next observation must
  make the `ViewTarget::DrawFrame()` API boundary explicit.
