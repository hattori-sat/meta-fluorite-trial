# FLR-0261 — trace current production scene stages after model selection

- Status: Done
- Priority: High
- Owner: Fluorite Filament ModelSystem / ViewTarget boundary
- Created: 2026-09-24
- Predecessor: [FLR-0260](FLR-0260-diagnose-black-production-render-content.md)

## Objective

Identify the first current-source boundary after production model selection
where scene content stops being renderable: GLB asset load, Scene insertion,
Renderable setup, Draw submission, or ViewTarget/scene binding.

## Facts

- FLR-0260's current-source stage-isolation A/B selected two Sequoia models and
  reached eight Vulkan queue-present markers, but ten QMP frames had zero
  chromatic pixels in ROI `[200,100,400,250]`.
- The same frame was a black upper area over a white lower surface, so this
  unit does not prove production geometry or lighting pixels.
- The current source already logs effective ViewTarget scene and frame
  boundaries, but the historical `MODEL_STAGE_SCENE_ADD_DONE` marker is not
  registered in the current recipe.
- The self-made native fixture remains QMP-visible in the repaired image, so
  a universal QEMU/Wayland pixel-loss explanation is insufficient.
- Source changes must be made in the persistent Mac Devtool source Git,
  committed there, generated by official Devtool rebase, registered once in
  `meta-fluorite-trial`, then built authoritatively on the fixed Mini PC.

## Hypotheses

1. Model selection/load is reported, but the current asynchronous asset path
   does not reach Scene insertion or leaves the Renderable set empty.
2. Scene insertion and Draw submission are positive, but the active camera,
   material, or lighting contract produces a black scene.
3. Scene content is positive internally and the remaining loss is at
   ViewTarget/Wayland composition. This is less likely but remains open until
   the scene-stage markers and QMP pixels are correlated in one run.

## Scope boundary

Use one diagnostic trace patch and one bounded no-input runtime. Do not change
camera, material, lighting, composition, or product behavior in this ticket.
The trace is environment-gated and must be off by default.

## Success criteria

- Official Devtool patch `0279` is generated from the current source commit and
  registered exactly once in the canonical layer.
- Mac official patch generation and source/diff gates pass; Mini
  `do_patch`, `do_compile`, and image build pass. The Mac Devtool workspace
  uses `externalsrc`, so its `flutter-auto` and split-component recipes do not
  expose a `do_patch` task; actual patch application is authoritative on Mini.
- One QMP-only runtime records model asset load, Scene insertion, Draw submit,
  Draw end, ViewTarget scene identity, Present, and bounded pixel statistics.
- The first scene-stage boundary is classified: model selection, asset load,
  Scene insertion, Draw submit/end, active default Scene, and Present are
  positive; the paired QMP candidate remains effectively black/grayscale.

## Verification plan

1. Generate `0279` through the persistent Mac Podman/Devtool container from
   the committed source delta.
2. Transfer a complete-history bundle to the fixed Mini receiver and reuse
   the existing build/TMPDIR.
3. Build the recipe and image, then run one QEMU with
   `FLR0026_SCENE_STAGE_TRACE=1` and no readback.
4. Capture ten no-input QMP frames, analyze ROI `[200,100,400,250]`, and run
   the bounded log slicer.
5. Stop the scoped app PID and quit QEMU through QMP; record residual checks.
