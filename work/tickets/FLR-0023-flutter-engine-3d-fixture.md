# FLR-0023 — Flutter Engine経由の最小3D fixture

- Status: Waiting
- Priority: High
- Owner: Flutter runtime + Filament bridge + target-validation roles
- Depends on: FLR-0019, FLR-0021
- External publication: none

## Problem

Vulkan初期化、Filament/native readiness、2D telemetryが成立しても、
「表示する3D objectがnative側で生成された」ことと「そのpixelがchild
Wayland surfaceへ渡った」ことはまだ証明されていない。フルsceneのshader、
asset、camera、frame-event負荷を切り離す最小fixtureが必要である。

## Goal

既存のFlutter Engine `SceneView` / `filament_scene` / `filament_view`契約を
使い、opaque clearと単純なtriangleまたはbox相当のrenderableを1つだけ生成し、
Dart payload、native entity/renderable、Filament frame completion、Wayland
child-surface commit、screen pixelを順に検証する。

## Facts already known

- Existing Dart patches adapt camera and shape/material payloads to the pinned v2
  native contract.
- Existing native patches include ViewTarget creation, ECS initialization,
  frame scheduling, and Flutter platform-runner event dispatch.
- FLR-0020's explicit launch on the prior diagnostic rootfs reached Vulkan and
  AOT loading but failed in Dart scene construction at
  `TrainsetSceneView.cameras`; that artifact did not contain this fixture.
- Historical revision `344238a1` produced an opaque blue diagnostic result in
  QEMU, but that bounded result did not prove the current transparent production
  composition path.
- Current FLR-0019 evidence has Vulkan/llvmpipe and parent-surface activity but
  no proven child-surface buffer attach/commit.

## Success criteria

- [x] Fixture source contains a deterministic non-empty 3D payload and an
  explicit expected camera/material/geometry contract.
- [x] `bitbake -e` confirms the fixture recipe and exact patch order; no full
  image build is used on Mac.
- [x] Devtool-generated fixture patch applies cleanly to a clean source
  checkout and is registered in the candidate recipe `SRC_URI`.
- [x] Camera-isolated follow-up patch is generated by Devtool and removes the
  known production camera null path from the fixture.
- [ ] Runtime logs prove native ViewTarget, entity, renderable, and frame
  completion in order.
- [x] Guest uses the fixed FLR-0019 profile (12 vCPU; Vulkan device recorded).
- [ ] Child Wayland attach/commit is observed and the screen hash/pixel evidence
  changes during at least a bounded 10-second run.
- [ ] If native creation succeeds but child commit remains zero, close this
  fixture as a causal boundary result and open a separate WSI/compositor ticket.

## Verification sequence

1. Static-map the existing Flutter Engine/platform-runner and Filament bridge
   calls; record the effective recipe patch list.
2. Prepare the fixture with Devtool in Ubuntu 22.04 Docker using only the
   fixture recipe's `patch`, `compile`, `install`, or `package` tasks.
3. Check the generated patch against a clean source tree before any bundle is
   created.
4. Build the fixture-containing diagnostic payload on the authoritative mini-PC
   only after revision/bundle verification.
5. Run the fixed QEMU profile and collect Dart payload, native creation,
   frame-boundary, Wayland protocol, and screen-hash evidence separately.

## Hypotheses

- H1: The existing scene payload is non-empty but its initial view message is
  lost before native systems/channels are ready.
- H2: The native renderable is created and rendered, but the transparent WSI /
  child-surface path prevents composition.
- H3: The fixture itself is empty or malformed after recipe packaging, so the
  runtime cannot display geometry even though the renderer initializes.

## UNKNOWN

- Exact fixture source path and package asset contents at the authoritative
  revision.
- Whether the historical opaque blue diagnostic was produced by a triangle,
  textured primitive, or only native clear plus an independent primitive.
- Whether a minimal opaque fixture is accepted by the current homescreen layer
  without altering production transparency settings.

## Latest validation checkpoint

- The Mac Docker/Devtool patch path prepared the fixture bundle; the
  authoritative mini-PC build consumed the exact committed revision.
- Fixture `do_patch`, fixture `do_compile`, and the complete
  `agl-ivi-image-flutter` build passed on the mini PC. The built AOT payload
  contains `flr0023_fixture_cube` and `poGetMinimal3dFixtureScene` markers.
- The fixed 12-vCPU qemux86-64 TCG session booted to the AGL graphical session.
  Explicit `agl-driver` launch reached Vulkan/Wayland, llvmpipe, Filament
  engine initialization, AOT loading, and `All systems initialized`.
- The app then exited with status 139 after loading `lit.filamat`; the QEMU
  window remained black. Native entity/renderable/frame completion,
  child-surface attach/commit, and pixel-change acceptance remain unproven.
- The full-scene clean-branch reference was compared at the same 12-vCPU
  boundary: its startup 2D/menu path worked, but its 3D region stayed black
  and Playground selection ended in an all-white state. This separates the
  fixture's package inclusion from the unresolved runtime display path, but
  does not yet isolate the first native crash frame.
- Four existing patch-series context/API drifts were corrected in the Mac
  feature branch before the successful image build: `0003`, `0015`, `0017`,
  and `0018`. The complete patch-series `do_patch` then passed.
