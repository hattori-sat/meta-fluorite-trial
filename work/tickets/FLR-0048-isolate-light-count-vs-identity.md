# FLR-0048 — isolate light-count versus native identity

- Status: Done
- Priority: High
- Owner: runtime diagnosis + Filament scene/resource + target-validation roles
- Depends on: [FLR-0047](FLR-0047-isolate-first-failing-light.md)
- Working log: `work/logs/2026-09-07-flr0048.md`

## Problem

FLR-0046 established an 8→9 selected-light boundary with `model=1` and
environment skipped. FLR-0047 showed that skipping GUID `162` and replacing it
with GUID `164` still fails. The remaining distinction is aggregate
light/resource state versus a later identity or downstream native operation.

## Success criteria

- Keep the current authoritative rootfs, model limit=1, and environment skip.
- Capture native light properties/state for the passing 8-light and failing
  9-light conditions, including replacement variants.
- Determine the smallest reproducible light/resource condition and the first
  downstream divergence (frame, queue, present, or error marker).
- Do not make a source patch until the runtime evidence identifies a
  controllable source/configuration boundary.
- Capture QMP-only images and verify clean QMP teardown for each decisive run.

## Plan / PDCA

### Plan

1. Reuse the fixed rootfs and one QEMU at a time; no build or source mutation
   is planned initially.
2. Compare limit=8 against limit=9 with GUID `162` excluded, while enabling
   existing light property/native state trace for the selected candidates.
3. If necessary, replace both GUID `162` and `164` in separate bounded runs to
   test whether a later identity reproduces the same failure.
4. Correlate native light state, model stage, frame/present, and QMP pixels.

### Facts

- Eight selected lights show the production GLB in QMP pixels.
- Nine selected lights show HUD-only pixels.
- Skipping GUID `162` and selecting GUID `164` for the ninth slot remains
  HUD-only.
- Model asset load and stage completion occur in the passing and failing cases.
- The first eight selected lights (GUIDs `126..140`) are `POINT` lights with
  `cast_shadows=false`, intensity `4e6` or `6e6`, and falloff `2`.
- GUID `162` is a `POINT` light with `cast_shadows=true`, intensity `2.4e7`,
  and falloff `300.1`. GUID `164` is also a shadow-casting point light.
- Excluding GUIDs `162` and `164` and selecting a later light as the ninth
  light remains HUD-only in QMP pixels.
- Filament's configured general light limit is `255`; nine lights do not reach
  that limit. Dynamic-light preparation and point-light shadow preparation are
  separate downstream paths.
- QMP teardown returned `SHUTDOWN reason=host-qmp-quit` for each added case;
  no QEMU, runqemu, or flutter-auto process remained afterward.

### Hypotheses

1. Aggregate light count/resource pressure at nine selected lights is causal;
   replacement identities will fail in the same way.
2. A later light identity (starting with GUID `164`) has a native property or
   operation that causes the first divergence.
3. Light setup is only correlated; frame/present synchronization is the actual
   first divergent process boundary.
4. The first shadow-casting point light activates a shadow-map path that fails
   before the model becomes visible; disabling shadow casting is a diagnostic
   test for this boundary.

### UNKNOWN

- Native property/state differences among GUIDs `126..170`.
- Whether GUID `164` or a later identity is individually sufficient.
- Whether environment stages alter the 8→9 boundary.
- Whether the shadow-caster diagnostic restores the model pixels.
- Whether a production fix should change the demo light data or the native
  shadow/render path.

- QMP quit returned `SHUTDOWN reason=host-qmp-quit`; the QMP socket and

## Conclusion

The first shadow-casting point-light path is not sufficient to explain the
9-light failure. Keep the diagnostic patch opt-in only; do not treat it as a
production fix. FLR-0048 is complete for its scoped light-count/identity
comparison; the remaining aggregate resource or later render/present boundary
is tracked independently in FLR-0049.
