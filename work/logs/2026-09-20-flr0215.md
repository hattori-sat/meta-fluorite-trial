# FLR-0215 working log — native surface compositor visibility

Date: 2026-09-20
Ticket: FLR-0215
Status: Done

## Outcome

Runtime and source evidence identify the remaining boundary as final native
surface composition. The ViewTarget creates the native child surface and
subsurface, the WSI attaches and commits an RGB-positive buffer, and the
compositor maps the same RGB-positive bytes. QMP nevertheless shows only the
2D HUD. No root-cause patch is made in this ticket.

## Facts

- Existing FLR-0214 runtime log records:
  `FLUORITE_VIEWTARGET_EFFECTIVE_CONTRACT scene_native=true` with
  `parent_surface=true surface=true subsurface=true`.
- The same log records `FLUORITE_NATIVE_WAYLAND_STACKING below=false`.
- Wayland protocol records native `wl_surface@37.attach(wl_buffer@50)`, damage,
  frame callback, and commit.
- Native present returns success and direct native readback ROI is positive.
- The first WSI mapping is RGB-positive in both app and compositor mappings,
  with first-five report SHA-256
  `9362aab17d4025e918ae9bf4f3eb5269550d9fc1369362a4b5c73b79158a1baf`.
- Native-only QMP frame SHA-256:
  `b133eeb9e9e1fe49188d717d3649a3aba3ebaf006643eafafd1b215605c05147`.
- Native QMP ROI is uniform black while the HUD ROI is chromatic and visible.

## Static source evidence

- `ViewTarget::setupWaylandSubsurface()` creates `surface_`, attaches it to
  `parent_surface_`, sets the native surface above the parent by default, sets
  its position, and selects desynchronized subsurface mode.
- `ViewTarget::InitializeFilamentInternals()` passes the same `surface_` to
  Filament's native window and creates the swapchain.
- `ViewTarget::DrawFrame()` calls `renderer->endFrame()`; the explicit
  `wl_surface_commit` is only an opt-in diagnostic path. The normal path
  relies on WSI present.

## Inferences

- The failure is not “Vulkan produced a black image” and not “SCM_RIGHTS lost
  the bytes”. It is “the RGB-positive native surface is not selected into the
  final parent framebuffer”.
- The source component owning the remaining boundary is the
  `fluorite-plugins` ViewTarget, while compositor policy remains an external
  possibility.
