# FLR-0222 working log — restore native WSI 3D display

Date: 2026-09-20
Ticket: FLR-0222
Status: In Progress

## Outcome

The first low-cost discriminator is complete. Adding only the existing visible
SHM initialization/roundtrip changes the native swapchain fallback extent from
`1280x720` to `1280x800`, but QMP still shows only the SHM child. Pixels outside
the SHM child are zero, so extent initialization is not sufficient to restore
native WSI display.

## Facts

- Fixed image, build, TMPDIR, receiver, and QEMU harness were reused.
- Preflight/start/guest-ready passed; exactly one flutter-auto was launched.
- Runtime selected `FLUORITE_NATIVE_VISIBLE_SHM_CUBE=1` without
  `FLUORITE_NATIVE_READBACK_TO_SHM`.
- Filament native target draw used `index_count=36` and reported
  `nonzero_pixels=111758 chromatic_pixels=111758`.
- Vulkan swapchain selected `chosen=1280x800 format=44 images=5` after the
  SHM initialization roundtrip.
- QMP screenshot SHA-256:
  `830fd73a5eb8ca51798dc037add59fcb37c9e3b5c3082f4d515c487fa0ab0cf4`.
- The central ROI contains the visible SHM child; left, right, and below-SHM
  ROIs were all `nonzero=0 chromatic=0`. Thus the native surface was not proven
  visible by this run.
- QMP quit and residual-process cleanup passed.
- Artifact hashes are indexed in
  `$EVIDENCE_ROOT/FLR-0222/flr0222-artifact-sha256.txt`.

## Inferences

- The earlier `1280x720` versus `1280x800` difference is an initialization
  ordering effect, but it is not the sole reason native WSI pixels are absent.
- The working SHM bridge remains a valid display control, not proof that native
  WSI import works.

## Hypotheses

1. Mesa/Wayland WSI import or export loses the native RGB buffer after present.
2. Native surface role/stacking/output selection differs from the SHM child.
3. Native buffer format/layout metadata is accepted by Vulkan but not composed
   as expected by the guest compositor.
