  running container between calls.
- The wrapper persists the build directory and Yocto cache through four named
  volumes: build, downloads, sstate-cache, and tmp. The AGL checkout is a
  read-only bind mount and the project checkout is a bind mount. These volumes
  are separate from the mini-PC build paths.
- The Docker context is `desktop-linux` and its configured endpoint is the
  Docker Desktop Unix socket. The CLI consistently returned that the Docker
  daemon could not be reached; container, volume, and image inspection were
  therefore unavailable.
- Host process inspection found `com.docker.backend` without a Docker Desktop
  GUI process. The socket timestamp was stale. A normal GUI launch did not
  replace the backend or restore the daemon.
- Docker Desktop logs report `backend time ... context deadline exceeded`, then
  the VM init service reports a fatal running-service failure and powers the VM
  off. The VM log also contains a no-free-space-to-extend-partition message.
- The host Data volume had approximately 8.4 GiB available at the audit time
  and was 96% full. Docker's raw disk image had a 60 GiB logical size and
  approximately 13 GiB of host allocation.
- A graceful TERM was sent only to the orphaned backend after the VM was
  already down; it did not exit. No Docker data, container, or named volume was
  deleted. No QEMU process was involved in this action.

#### Inferences
