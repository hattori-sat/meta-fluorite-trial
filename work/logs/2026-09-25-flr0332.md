## Static call-path findings

- In the persistent Mac Devtool `flutter-auto-reconcile` source,
  `FlutterView::CreateSurface()` constructs `CompositorSurface` and calls
  `InitializePlugin()` immediately. `InitializePlugin()` calls the plugin's
  `m_api.initialize()` and then unconditionally calls `StartFrames()`.
- `StartFrames()` invokes `on_frame()` synchronously. `on_frame()` calls the
  plugin `draw_frame()` and then queues a Wayland frame callback and calls
  `wl_surface_commit(m_wl.surface)`.
- `FlutterView::RunTasks()` also calls the compositor plugin's `run_task()` for
  every registered surface. The source has no Light/camera/material guard on
  this publish path.
- `ViewTarget::OnFrame()` in `fluorite-plugins` explicitly documents that it
  must not call `wl_surface_commit()` because the commit happens elsewhere.
  Its optional `FLUORITE_NATIVE_WAYLAND_COMMIT` is therefore a diagnostic
  override, not the normal ownership path.
- This creates a bounded source/runtime discrepancy: FLR-0331 saw the native
  surface and subsurface registration but no native attach/damage/commit,
  while the inspected source expects the Flutter compositor-surface boundary
  to issue the commit after `draw_frame()`. The remaining candidates are the
  effective image's patch/compile path, the selected plugin API/module, or a
  runtime call that never reaches `on_frame()`.

## Correct owning path: NavRenderSurface

- A second static pass found that the `wl_surface@39` path is owned by
  `fluorite-plugins/plugins/nav_render_view/NavRenderSurface`, not by the
  generic `flutter-auto` `CompositorSurface` path.
- `NavRenderSurface` creates the native surface and subsurface in its
  constructor and only calls `wl_subsurface_set_desync()` there. It does not
  start a frame in the constructor.
- Its `on_frame()` calls `DrawFrame()`, registers a surface frame callback,
  positions the subsurface, and calls `wl_surface_commit(surface_)`.
- The only static entry that starts the first frame without an existing
  callback is `SetOffset()`, which calls `on_frame(this, callback_, 0)` when
  `callback_` is null. `SetOffset()` is reached from the platform-view
  `set_offset` listener.
- FLR-0331's Wayland trace exactly matches constructor-only progress:
  `create_surface → get_subsurface → set_desync`, with no `set_position`,
  `frame`, `attach`, `damage`, or `commit` for the native surface.

### Ranked hypotheses after source/runtime correlation

1. **H1 — initial `set_offset` is not delivered.** Prediction: a one-shot
   marker at `on_set_offset` remains absent, and adding an opt-in constructor
   start would produce the first native commit.
2. **H2 — `set_offset` is delivered but `on_frame`/DrawFrame does not return.**
   Prediction: `on_set_offset` is present but the `on_frame`/post-draw marker
   or native Wayland commit remains absent.
3. **H3 — a native buffer is attached but WAYLAND_DEBUG misses it.**
   Prediction: a targeted `on_frame`/post-commit marker is present even when
   the protocol trace is incomplete. FLR-0331 currently provides no such
   marker.

The next probe is therefore limited to the NavRenderSurface trigger boundary;
it will not change Light, camera, materials, scene ownership, or stacking.
