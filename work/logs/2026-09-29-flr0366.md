- At 13:58:32 guest time, kernel 6.6.111 reported `BUG: unable to handle page fault` at CR2 `0x000000008d207750`, `#PF supervisor read access in user mode`, TID `FEngine::loop`, RIP `0x7fffefb4f541`, RSP `0x00007fff8d207750`. The low 32 bits of RSP equal CR2. Two `FLR0026_VK_QUEUE_PRESENT_BEGIN` markers and one `result=0` were observed; the Oops followed. This is correlation, not causation.
- `/usr/lib/libLLVM.so.18.1` Build-ID `359c1108040bc6bc1af64bb639d0b25385858051`; mapped range started `0x7fffef86a000` at file offset `0x838000`, giving load bias `0x7fffef032000`. Correct ELF virtual address is `0xb1d541`; symbol is `llvm::CmpInst::isOrdered(llvm::CmpInst::Predicate)`. Disassembly: `dec %edi; cmp $0x7,%edi; setb %al; ret`. The function itself has no direct memory access in these instructions. No `.debug_*` sections or split-debug file were found; `coredumpctl` recent listing had no entries.
