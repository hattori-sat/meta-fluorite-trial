# FLR-0100 working log — Vulkan present return boundary

## Plan

Use the fixed image and one QEMU at a time to identify the runtime owner of
the production `vkQueuePresentKHR` non-return. Collect bounded process,
backtrace, and syscall evidence before proposing any source change.

## Facts

- FLR-0099 fixture returned from queue-present and produced native pixels.
- FLR-0099 recovered production reached queue-present enter but remained
  native-black with no return marker.
- The first GDB collection produced 48,350 bytes and exited with `GDB_RC=0`,
  but the harness did not observe its completion marker within the serial
  window. It is retained as a failed collection attempt.

## Inferences

- The next cut is thread/syscall ownership at the present call.

## Hypotheses

1. An unsignaled submit/present semaphore is waited on in software Vulkan.
2. Software-Vulkan command or target-transition work blocks before return.
3. The existing bounded collection ended before a delayed return.

## UNKNOWN

- The blocked thread and exact wait operation.
- The exact current-run mapping base and source-level producer of the fault.

## Do / Check / Act

### Do

1. Reused the fixed Mini image, receiver, build/TMPDIR, one QEMU run alias,
   and QMP-only capture contract.
2. The oversized GDB collection failed the serial completion-marker contract;
   no runtime conclusion was taken from the incomplete harness result.
3. A local post-processing command had a shell quoting error; it made no
   remote or runtime change and was recorded as an invocation error.
4. The retry waited for the present markers and captured the guest Oops:
   `BUG: unable to handle page fault for address: 00000000d8a41750`,
   `CPU: 1 PID: 680 Comm: FEngine::loop`,
   `RIP: 0033:0x7f753fde4541`, and
   `CR2: 00000000d8a41750` after
   `FLR0026_VK_QUEUE_PRESENT_BEGIN`.
5. Mini `nm -D` mapped `isOrdered` to `0xb1d540`; the retry RIP is at the
   same `+0xb1d541` boundary previously directly mapped by FLR-0030.

### Check

PASS: the current production run reaches queue-present entry and then faults
inside `FEngine::loop` before queue-present return. This explains the missing
return marker. QMP before/early artifacts and the guest Oops are retained;
QMP quit accepted and residual checks are PASS. The direct current-run
`/proc/<pid>/maps` snapshot and exact upstream producer remain UNKNOWN.

### Act

Close FLR-0100 as an evidence-only boundary ticket. Continue with FLR-0101,
which isolates the smallest production model/resource input using a single
runtime variable at a time. No present or synchronization patch is justified
by this ticket alone.
