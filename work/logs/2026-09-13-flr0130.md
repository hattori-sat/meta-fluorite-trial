# Working log — FLR-0130 (2026-09-13)

## Correction to initial diagnosis

- The initial “receiver is missing” diagnosis was wrong because the inspected
  Mac source was a different API generation (`onSystemInit/registerMessageHandler`)
  from the Mini recipe source (`vOnInitSystem/vRegisterMessageHandler`).
- The actual Mini source already registers
  `SetCameraFromDeserializedLoad` and calls
  `vSetCameraFromSerializedData()`.
- The real contradiction was that `CameraManager::setDefaultFilamentCamera()`
  installs a default Filament camera before the Dart payload arrives, while
  the old `vSetCameraFromSerializedData()` skipped ViewTargets with an existing
  primary camera. The existing ViewTarget replacement API was therefore never
  used for the normal path.

## Plan

- Restore the native receiver for the Dart `scene.camera` payload.
- Keep the normal lit Dart fixture, ViewTarget blend mode, lighting, scene
  content, and QEMU profile unchanged.
- Use one current-source Mac Devtool patch, one Mini image, and one QMP-only
  runtime run.

## Facts

- The canonical repository check passed before this ticket was created.
- `SceneTextDeserializer::vRunPostSetupLoad()` constructs a
  `SetCameraFromDeserializedLoad` ECS message containing a raw `Camera*`.
- `ViewTargetSystem::vOnInitSystem()` already registers the same message in the
  Mini API generation and transfers ownership exactly once after cloning.
- `ViewTarget::setupView()` attaches the common Filament Scene and creates a
  `CameraManager`; the manager immediately installs a default Filament camera.
- `ViewTarget::vSetupCameraManagerWithDeserializedCamera()` updates that
  Filament camera and replaces the plugin primary camera.
- The old primary-camera guard was removed by the current-source Devtool patch;
  the generated patch is canonical `0239`.
- FLR-0129 runtime evidence showed one `flutter-auto`, Dart-side
  `Camera 8 enabled`, `FLR0026_SHAPE_READY`, Vulkan submit/present activity, and
  a black central 3D region. Native camera-application markers were absent
  before this ticket.
- The FLR-0130 rerun shows `FLUORITE_DESERIALIZED_CAMERA_RECEIVED` and
  `FLUORITE_DESERIALIZED_CAMERA_APPLIED`, Shape `renderable=true`, submit return
  `0`, and present activity. QMP early/late fixed-region analysis remains
  uniform black; full-frame indicators are HUD/controls only.

## Inferences

- The missing-route hypothesis is falsified for the actual Mini API generation.
- The default-primary guard was a real handoff defect, but its correction is
  insufficient to produce visible Dart 3D pixels.
- The remaining boundary is whether the renderable reaches a Filament Draw,
  and if so whether a valid draw is hidden by the ViewTarget/Wayland output.
