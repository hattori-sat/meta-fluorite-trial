# FLR-0030 working log — present-boundary fault symbol mapping

## Plan

- Reuse the exact FLR-0029 image/profile and fixed QEMU evidence root.
- Attach GDB before the first frame, capture loaded maps, and resolve the fault with guest tools and authoritative build symbols.
- Preserve a QMP-only image and terminate QEMU through QMP.

## Facts

- The attach run used one QEMU instance and started the Example Demo with the same model/environment skip, sync trace, and forced-render flags as FLR-0029.
- GDB attached before the first frame. The main `flutter-auto` thread was in `ppoll`; other Flutter and llvmpipe threads were waiting in futex calls.
- The runtime reached `FLR0026_VK_QUEUE_PRESENT_BEGIN` and then reported a page fault in `FEngine::loop`: `RIP: 0033:0x7fafecda5541`, `RSP: 002b:0x7faf8eff9750`, `CR2: 0x7faf8eff9750`.
- `/proc/<pid>/maps` showed `/usr/lib/libLLVM.so.18.1`. Relative RIP offset is `0xb1d541`.
- Guest `eu-addr2line` resolved `0xb1d541` to `llvm::CmpInst::isOrdered(llvm::CmpInst::Predicate)`, with `??:0` for the source line.
- The authoritative Mini PC build has `isOrdered` at `0xb1d540`; `objdump` shows the first instruction begins `ff cf`, so RIP `0xb1d541` is one byte into that instruction. No matching `.debug` file was present in the build outputs.
- QMP-only late frame is 720x400 HUD-only with no native 3D. Local PNG SHA-256: `4b7f4270262d786b4a3b09a0ff3770ef7851c520fa7cd4fe10284a96131312ae`.
- Serial SHA-256: `6ec1a5dcd2e1236d220125d2093de411c7e140029222c36d1f3b6c526466de91`. QMP quit evidence SHA-256: `511117bfd4ec27607ee752999f10a4d8140f6af90a40f26fe25b838609d6bb8c`.
- QMP quit completed; the socket was absent and no actual QEMU/Flutter/Weston process remained.

## Inferences

- The first mapped fault boundary is the userspace LLVM library used by the llvmpipe/Vulkan path, after present begins.
- A one-byte-into-function RIP suggests corrupted control flow, return state, or an invalid indirect target is plausible. This is not proof that `isOrdered` itself is the producer.
- QMP capture and Wayland screenshot acquisition are not the first failing layer for this run.

## Hypotheses

1. Lit material/light work triggers the invalid control-flow state.
2. One light type or parameter is the smallest trigger.
3. Present/synchronization diagnostics change timing or stack state.
