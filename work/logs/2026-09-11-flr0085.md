# FLR-0085 — retire legacy receiver artifacts

## Plan

Remove the old `FLR0026` receiver artifacts from active Mini PC paths without
rewriting historical repository evidence. Record hashes before the move,
archive the exact objects under a neutral path, and verify the fixed receiver
and inbox remain the only active handoff locations.

## Facts

- Current active receiver: `/mnt/yocto/flourite-receivers/flr0023-835a04e`.
- Current active inbox: `/mnt/yocto/flourite-receivers/inbox`.
- Old active-path artifacts: two evidence directories and ten bundles, all
  created on 2026-09-05.
- The old directories were 5.7 MiB each; the bundles were approximately
  1.2–1.3 MiB each.

## Inferences

- The old name survived because handoff attempts accumulated per-attempt
  bundles without a bounded retention/archive rule.
- It is safe to retire the active-path names after checking the fixed receiver
  and finding no references to them.

## Hypotheses

- The old paths might be needed by a current process. This was checked against
  the receiver root and no active reference was found.

## UNKNOWN

- Other hosts may have independent historical copies; this task covers only
  the Mini PC receiver tree.

## Do / Check / Act

- Do: recorded SHA-256 manifests for all old bundles and every file in both old
  evidence directories before moving them.
- Do: moved them to
  `/mnt/yocto/flourite-receivers/archive/legacy-runtime-2026-09-05/` using
  neutral `run-*` names.
- Check: the old `evidence/` and `inbox/` active roots no longer contain
  `FLR0026`-named directories or bundles.
- Check: the fixed receiver and inbox were not moved or modified.
- Act: added the history-only naming rule to `TASKS.md` and
  `docs/environment.md`; future work uses the current ticket and
  `FLUORITE_*` names.
