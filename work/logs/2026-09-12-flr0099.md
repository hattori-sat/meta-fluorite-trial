Use the recovered current-image frame condition to compare production with the
positive fixture at draw-target, content, submit/present, and native-surface
boundaries. Keep the run bounded, QMP-first, and one-QEMU-at-a-time. Do not
patch until the first missing operation is evidenced.

## Facts

- FLR-0098 proved that the existing ready control recovers production frame
  begin/end and draw-target setup, but native pixels remain zero.
- The fixture reaches native pixels under the same image/build contract.
- Existing draw/surface markers use historical names in the current image; no
  new legacy namespace is being created.

## Inferences

- Target identity/content must be correlated before changing surface or
  synchronization behavior.

## Hypotheses

1. Production draws to an offscreen/non-visible target.
2. Production visible target receives no effective scene content.
3. Production submits native content but the surface handoff remains stale or
   hidden.
4. Existing markers are insufficient.

## UNKNOWN

  visible native surface.

## Do / Check / Act

### Do

1. Inspected the effective Filament patch seams. `TARGET_DRAW2` is emitted
   from `VulkanDriver::draw2`; outer present markers surround
   `VulkanSwapChain::present`; queue-present markers surround the
   `vkQueuePresentKHR` call in `VulkanPlatformSurfaceSwapChain::present`.
2. Reused the fixed authoritative image, fixed build/TMPDIR, fixed receiver,
   and one short QMP alias. The fixture and recovered production cases used
   the same QMP regions, bounded waits, neutral lifecycle/submit/present/fence
   and pipeline-input traces, and one-app launch guard.
3. Captured QMP before/early/late frames and six-frame QMP videos, extracted
   selected guest markers, and recorded the single `flutter-auto` process with
   the compositor for each case.
4. Stopped each QEMU through negotiated QMP `quit`; both cases passed the
   residual target and QMP socket checks.

### Check

- Fixture reached visible `TARGET_DRAW2 swapchain=true extent=1280x800
  index_count=36`, queue-present return `result=0`, outer present return and
  present-done. Its late native region was `41,750/223,200` pixels with
  bounding box `[501,278,278,162]`; HUD was `6,240/100,000`.
- Recovered production reported valid scene/resource state and reached
  offscreen draws, a visible `swapchain=true extent=1280x800 index_count=3`
  draw, and `FLUORITE_VK_QUEUE_PRESENT_ENTER wait=true`. It produced no queue
  present return, outer present return, or present-done marker. Its late native
  region was `0/223,200`; HUD was `984/100,000` with bounding box
  `[200,113,29,66]`.
- Production's six QMP video frames were byte-identical; fixture video frames
  changed over time. The first observed divergence is therefore the return
  from `vkQueuePresentKHR`, not the existence of a draw-target record.
- No explicit runtime error marker appeared in the selected production log.
  The blocked thread/wait owner remains UNKNOWN.
