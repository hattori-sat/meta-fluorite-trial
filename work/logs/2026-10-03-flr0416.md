## Iteration 3 — fail-closed cursor and abort-window review (2026-10-03)

### Facts

- GPT-6.1 Sol's prior read-only review found two remaining observer hazards:
  journalctl may resolve a missing cursor to a nearby surviving entry, and
  stage exceptions had no explicit identity-bound abort attempt.
- systemd documents that cursor seek may use the nearest available entry if
  the requested entry is absent. The guest observer now probes the saved
  cursor with a bounded `journalctl --cursor=... --lines=+1 --show-cursor`
  query and requires exactly one returned cursor equal to the saved anchor
  before requesting records after it. A rotated-out or ambiguous anchor fails
  closed; exact empty output is zero new records only after that probe.
- Host abort publication now has a separate monotonic 50-second deadline
  inside the guest's 60-second grace. Serial calls are capped against the
  remaining abort time. On stage exceptions, an exact-identity abort is
  attempted unless the guest release ACK was already validated; load stage
  may first recover the identity from its create-only `armed.json` record.
  Unknown identity and abort-publication failure are preserved as explicit
  errors rather than silently treated as success.
- The new process-owner test now uses `devtool status`; its previous fixture
  included `flutter-auto` as a devtool argument and therefore intentionally
  triggered both keyword classifications.
- FLR-0416 remains an observer-only diagnostic on the unchanged FLR-0410 image.
  No Mini connection, QEMU, BitBake, image, cache, or product-source operation
  has been performed in this iteration.

### Inferences

- The extra exact-cursor query closes the false-empty window from cursor
  rotation or nearest-entry fallback, subject to confirmation against the
  target image's systemd/journalctl implementation at runtime.
- The separate abort budget prevents blocked abort-transfer work from
  consuming more than the guest's remaining abort grace, subject to timing
  and serial behavior on the target.

### Hypotheses

- If the exact anchor probe returns its supplied cursor, `--after-cursor`
  snapshots can distinguish a quiet journal from an expired/rotated anchor.
- If a stage fails before validated release acceptance and identity remains
  verifiable, the bounded abort can stop the guest without auto-continuing.

### UNKNOWN

- Exact-cursor command behavior and journal rotation under the FLR-0410 guest's
  installed systemd version.
- Actual transfer latency, GDB callback timing, observer liveness, and whether
  the target consumes the identity-bound abort inside the available grace.
- The complete FLR-0416 runtime observation and all product-render gates.

## Iteration 4 — stage-clock anchoring and release-outcome evidence (2026-10-03)

### Facts

- GPT-6.1 Sol's second judgment-only review found the ACK clocks started too
  late: guest load wait can begin during GDB launch, and guest hit wait can
  begin while the host verifies the load release. It also identified that a
  published release with an unavailable ACK does not prove the inferior is
  still held, and that a cursor probe and `--after-cursor` read use separate
  journal openings.
- The load collection deadline is now started immediately before GDB/Example
  Demo launch. The hit deadline is prepared immediately before load-release
  publication and adopted by the hit stage without resetting its clock.
- Stage evidence now distinguishes release publication (`NOT_STARTED` /
  `IN_PROGRESS` / `PUBLISHED` / `UNKNOWN`) from guest acceptance
  (`UNKNOWN` / `ACCEPTED`). If release publication succeeded but acceptance
  could not be validated, the record explicitly sets the inferior-held state
  to `UNKNOWN_IF_RELEASE_PUBLISHED`; outer failure handling performs exact
  QMP teardown and does not claim the target remained stopped.
- The saved kernel cursor is now checked before and after the bounded
  incremental journal read. If the anchor changes or resolves to a nearest
  entry at either end, the snapshot fails closed. Snapshot serial bound was
  raised to 45 seconds to cover the bounded guest query set.
- Official systemd `journalctl(255)` documentation defines `--cursor`,
  `--lines=+N`, and `--show-cursor` behavior. systemd's journal API docs warn
  that seeking an unavailable cursor may choose the nearest entry. This is
  implementation guidance only; the target image's actual version/behavior
  remains unverified:
  [journalctl(255)](https://www.freedesktop.org/software/systemd/man/255/journalctl.html),
  [cursor-seek nearest-entry discussion](https://github.com/systemd/systemd/issues/6213).
- No Mini connection, QEMU, BitBake, image, cache, or product-source operation
  has been performed in this iteration.

### Inferences

- Carrying deadlines from the actual guest-wait entry boundaries prevents the
  host from silently adding a fresh 540 seconds after GDB launch or load ACK.
- Pre/post cursor probes detect normal rotation during an incremental read,
  but separate journalctl processes do not provide a transactional snapshot.

### Hypotheses

- On the target image, the exact cursor probe will either preserve one stable
  anchor across the incremental read or fail closed on rotation/nearest-entry
  fallback.
- A release ACK miss will remain explicitly ambiguous while exact teardown
  prevents the diagnostic run from being mistaken for a held-process result.

### UNKNOWN

- Atomicity/continuity under target journal rotation between separate probes.
- Target image's installed systemd version and its actual `journalctl` output
  for the anchor-probe command.
- Guest wait timing, delivery/acceptance of a bounded abort, live GDB/QMP
  correlation, and all product-render acceptance criteria.
