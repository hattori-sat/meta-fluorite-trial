## Hypotheses

1. Flutter embedder loses parent clear/alpha during pointer-triggered repaint.
2. The compositor imports the parent buffer as opaque after input damage.
3. Native child-surface ordering changes on input; current evidence makes this
   low probability.

## Inferences

- Explicit parent-alpha clearing did not prevent the input-triggered white
  parent/HUD frame. The working boundary remains the Flutter parent repaint or
  its Wayland compositor import/damage handling, after the native 3D producer.
- Because the native ROI is unchanged and no native child reattach appears in
  the bounded transition log, native geometry/light/camera code is not the
  immediate explanation for this white transition.
