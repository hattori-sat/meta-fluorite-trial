## Iteration 2 — close the input-echo false-ready path (2026-10-02)

### Facts

- The prior one-phase command included its nonce in the bytes sent to the
  interactive shell. If TTY echo remained enabled, the echoed input could
  contain the nonce before `printf` executed. The earlier mock omitted that
  echo behavior, so its 11/11 and 227/227 PASS results did not test this case.
- Read-only GPT-6.1 Sol review agreed with a two-phase gate and additionally
  called out chunk-split duplicate prompts and stale fixed completion markers.
- No product source, Yocto recipe, image, build cache, Mini receiver, or QEMU
  was changed in this iteration.

### Inferences and decision

- A nonce-free `stty -echo` command followed by a nonce-bearing status probe
  separates command input from proof of output. Requiring one exact status line
  with status 0 and one nonce occurrence rejects an echoed probe.
- Prompt is only a sequencing/completion barrier. A 50 ms quiet window catches
  adjacent prompt bytes split across reads; it is explicitly bounded and does
  not assert that no later serial bytes can ever arrive.
- A unique completion nonce per guest command prevents a prior invocation's
  fixed marker from reporting false completion.

### Do

- Replaced the one-phase setup command with nonce-free
  `stty -echo; __FLR_SERIAL_STTY_RC=$?`, then a second nonce-bearing
  `printf` probe. Guest command dispatch is blocked until status 0, exactly one
  nonce in the complete received probe transcript, and a single final prompt
  after the status line are verified.
- Added a 50 ms bounded quiet check for duplicate prompt residue arriving in a
  later TCP read, and changed each guest command's completion marker to a fresh
  per-invocation nonce.
- Extended the local mock for echo initially enabled/already disabled, echoed
  probe, failed `stty`, split duplicate prompt, missing marker, stale fixed
  completion marker, exact-once dispatch, nonzero guest status, and global
  deadlines.
