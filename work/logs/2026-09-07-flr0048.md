# FLR-0048 working log — light count versus native identity

Status: Done

## Plan

- Reuse the fixed authoritative rootfs and QEMU profile.
- Keep model limit=1 and environment skip fixed.
- Trace selected light properties/native state around the 8→9 boundary.
- Capture QMP-only screenshots before considering a patch.

## Facts

- FLR-0046: eight lights pass, nine lights fail with model=1.
- FLR-0047: skipping GUID `162` and selecting GUID `164` as the ninth light
  still fails.
- The full selected-light trace shows GUIDs `126..140` have
  `cast_shadows=false`; GUID `162` has `cast_shadows=true`, intensity `2.4e7`,
  and falloff `300.1`.
- A 9-light run excluding GUIDs `162` and `164` still produced HUD-only QMP
  pixels, so a single identity is not yet the explanation.
- Static Filament inspection found a general light limit of `255`, while
  shadow-casting point lights enter a separate shadow-map preparation path.
- The added QMP cases were terminated with `SHUTDOWN reason=host-qmp-quit` and
  no residual runtime process.

## Inferences

- GUID `162` alone is not sufficient to explain the failure.
- The next useful boundary is native light state and replacement identity, not
  another Flutter or Wayland global probe.

## Hypotheses

1. Nine-light aggregate state is the trigger.
2. GUID `164` or a later light identity is the trigger.
3. The light change exposes a frame/present synchronization divergence.

## UNKNOWN

- Native state/property comparison and first downstream divergence.
- Environment effect on this boundary.
- Whether a source patch is necessary.

## Decision

The current leading hypothesis is the first shadow-casting point-light path,
not the general nine-light count. This remains a hypothesis until a diagnostic
build with `FLR0026_NATIVE_LIGHT_DISABLE_SHADOWS=1` is run.

## Check

- Devtool generated the opt-in shadow-caster diagnostic patch. The layer
  registration was committed at project revision `220232e7` and transferred as
  a Git bundle to the fixed receiver.
- Mini PC gates passed: `flutter-auto:do_patch` 104/104,
  `flutter-auto:do_compile` 2686/2686, and full image 11748/11748.
- The valid run used `FLR0026_NATIVE_MODEL_LIMIT=1`,
  `FLR0026_NATIVE_SKIP_ENVIRONMENT=1`,
  `FLR0026_NATIVE_LIGHT_LIMIT=9`, and
  `FLR0026_NATIVE_LIGHT_DISABLE_SHADOWS=1`.
- QMP-only capture: 1280x800, PPM SHA-256
  `5748ebf361f40f37d374c8be18940fc2be59e968f231a9106f7d7b0cb8644589`,
  changed region 856/100000, bounding box `[200,113,29,66]`; no 3D object
  pixels were present.
- The deployed `/usr/bin/flutter-auto` contains the diagnostic environment
  variable string. QMP quit returned `host-qmp-quit` and no QEMU/runqemu/
  flutter-auto process remained.

## Act

The shadow-caster hypothesis is rejected as the sufficient cause. Keep patch
0194 as an opt-in diagnostic record and track the post-9-light aggregate
resource or render/present boundary in the independent FLR-0049 ticket. Do not
change the production default based on this negative result.
