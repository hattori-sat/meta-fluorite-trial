## Iteration 2 — explicit FIFO exec gate (static and host-shell checks only)

### Facts

- Astra's judgment-only comparison selected the FIFO token gate over the
  self-`SIGSTOP` wrapper. The gate separates GDB attachment from permission to
  exec Flutter. Astra also warned that this does not protect against GDB loss
  after the token; post-release debugger loss invalidates the run and requires
  teardown.
- The implementation uses Linux FIFO `O_RDWR` on the wrapper's fd 3, then
  builtin `read(3)` for exactly `FLR0350_GO`. Linux `fifo(7)` documents that
  opening a FIFO read/write succeeds on Linux, while POSIX leaves it undefined:
  [Linux `fifo(7)`](https://www.man7.org/linux/man-pages/man7/fifo.7.html).
  This is appropriate only for the pinned Linux guest and still requires
  target proof of `/proc/<pid>/syscall`, fd target, UID, and start identity.
- Added `FLR-0350-preflight.cmd`,
  `FLR-0350-launch-paused-production.cmd`, and
  `FLR-0350-release-go.cmd`. Preflight checks the existing guest GDB/Lavapipe,
  free run-owned paths, memory, Wayland socket, shell `kill`, FIFO/stat/timeout
  tools, and `/proc/self/syscall`. Launcher records a mode-0600 FIFO, wrapper
  PID/start time, and only reports PASS when that same shell is blocked in
  `read(3)` on the exact FIFO. Release checks the marker, PID/start identity,
  GDB `TracerPid`, FIFO descriptor and read syscall; the token writer is bounded
  with `timeout 2` and same-PID exec is polled for at most two seconds.
- Static validation passed: all 3 serial commands parse with `sh -n`, are
  1,144 / 2,723 / 2,390 bytes (each below 4,096), and the extracted inner
  wrapper body parses. A targeted comparison confirmed all `FLR_*` /
  `FLUORITE_*` variables and Flutter CLI arguments exactly match FLR-0344.
- A host-shell FIFO simulation passed both fail-closed cases: a wrong token
  exited 72 without reaching the exec sentinel; the exact token reached the
  sentinel. Scope is host shell only; it did not test the Linux guest's
  `/proc`, GDB ptrace state, or runtime symbols. The shell printed two
  `nice(5) failed: operation not permitted` warnings while starting background
  jobs; both test assertions passed and the temporary directory was removed.
- No Mini command, GDB, QEMU/runqemu, build, product source, patch, or image
  mutation occurred in this iteration.

### Inferences

- The FIFO and marker make pre-exec authorization inspectable, but do not
  establish post-exec symbol coverage. The GDB script must stop at exec and
  Lavapipe load, verify Build ID and resolved locations before relevant calls,
  and retain a bounded controller path.
- `O_RDWR` avoids a separate long-lived writer process and an unbounded FIFO
  open. It is Linux-specific (not portable POSIX); the guest preflight/run must
  fail closed if fd/syscall evidence differs. A bounded writer timeout limits
  the release race if the wrapper exits between checks and the write.
- Host-shell test success is not runtime success and is not evidence that
  Sequoia, the HUD, or 3D pixels appeared.

### Hypotheses

1. The FLR-0335 Linux guest's shell uses fd 3 for its builtin FIFO `read`, and
   `/proc/<pid>/syscall` plus `/proc/<pid>/fd/3` will uniquely prove it is
   blocked at the intended gate.
2. Target-specific proc formatting, permissions, or process state may differ;
   if so, the gate must stop before sending `FLR0350_GO` rather than infer a
   blocked read from `comm=sh` or a sleeping state alone.
3. Even with the FIFO gate, exec/library event handling or symbol loading may
   not be provable before the first relevant call. If so, FLR-0350 remains
   UNKNOWN and does not proceed to the 10-second observation window.
