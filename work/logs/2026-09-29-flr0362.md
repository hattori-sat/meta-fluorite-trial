## Failure-path re-review — queued GO and GDB detach semantics

### Facts

- Historical results remain scoped: FLR-0286 is the self-made lit Filament fixture plus HUD; FLR-0287 is production Sequoia with draw/present but zero-chroma ROI; FLR-0356/0358 are helper/framing failures; FLR-0359/0360 reach the measured `read(0)`/FD0+FD3 identity but stop before GDB/GO. I use them as discriminators, not as proof that this current gate works.
- Astra's earlier review correctly flagged that a GO record can fail after FIFO bytes have been queued. My subsequent code review found a missing process-lifecycle edge in the then-current plan: merely raising a GDB error does not prove that the ptrace-stopped target stays stopped when batch GDB exits. The GNU GDB manual distinguishes `kill` (terminates the inferior) from `detach` (allows it to run): [GDB inferior commands](https://sourceware.org/gdb/current/onlinedocs/gdb.html/Inferiors-Connections-and-Programs.html).
- A new regression test was added first and failed as expected because `wait_for_go_record()` did not terminate the inferior on invalid/expired GO state, and cleanup could interrupt GDB before protecting a queued token.

### Decision

- Preserve the already measured production wrapper and current write-then-record handshake. On GO record mismatch/timeout, GDB first kills only its exact selected inferior; if GDB's kill command fails, it attempts `SIGKILL` only after PID/start/UID/tracer match, then holds the ptrace session until termination is observable.
- Add a readable guest interrupt helper. Before sending GDB `SIGINT`, it validates the observer's protected run identity, GO record, and same-PID exec marker; if exec is not recorded or GO authority is invalid, it kills only the recorded target PID after PID/start/UID checks. If that cannot be proved, it refuses to interrupt GDB and reports cleanup failure rather than risk resuming a queued token.
- This closes the reviewed unsafe window while keeping the normal GO path and runtime image unchanged. A failed post-write publication is recorded as “bytes written; target termination required,” never mislabeled as zero-byte failure.

### Plan / Do / Check / Act

- **Plan:** test the GDB abort and cleanup ordering, then implement those exact-PID guards before any Mini transfer.
- **Do:** added the first contract tests; the GDB abort test was red before implementation. Added `terminate_stopped_inferior()` with GDB `kill`, a same-PID/start/UID/tracer SIGKILL fallback, and a hold-until-dead path if neither termination can yet be confirmed. Added `FLR-0350-interrupt-gdb.sh`; it checks the protected identity, live target start/UID/tracer/executable, GO record, and exec evidence, and kills only the exact run-owned target before sending GDB SIGINT when the GO/exec boundary is not proven.
