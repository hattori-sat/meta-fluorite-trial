## Iteration 2 — command-execution trace on current minimal geometry (p16)

### Facts

- Reused the fixed current 0208 rootfs, kernel, qemuboot profile, receiver,
  and one QEMU owner. The run directory was `$QEMU_EVIDENCE_ROOT/flr0081/p16`.
- `preflight`, `start`, `guest-ready`, `serial-exec`, and the single-process
  check passed. The app was launched once with skip-model, skip-environment,
  minimal geometry, ready-fence, force-render, sync trace, and the existing
  command-execution trace switch.
- Five QMP-only captures were byte-identical:
  `d4e96a65fd4f8e97bc1d762fc90cf2593bc2efb53a3125a72502fdae0f09395c`.
  Candidate region was `0/223200`; HUD region was `0/100000`.
- Runtime output contained 31 renderer-commit enqueue markers, 31 unlinked-
  fence-ready markers, and three sampled `FRAME_BEGIN started=true` markers.
  It contained zero command-execution-begin, queue-present, and commit-done
  markers.
- `strings /usr/bin/flutter-auto` found the command-execution, commit, and
  queue-present marker strings. The trace is therefore present in the image,
  but no execution marker was emitted during this profile.
- Evidence hashes: `runtime-markers-output.log`=
  `b394e6e033df8536e7ca07e9d5ab6ebc86535de187a4d3cce5023e11d8283e43`,
  `pixel-analysis.log`=
  `9aa1281d8d1f22c9e828176b09f94389c4336fdff8f9a69dc460c6ee9005a836`,
  `binary-markers-output.log`=
  `e4078a9774aa1b238966fba6c3c4785c787c32d1bc359d638063ecdb5414b453`.
- QMP `quit` was accepted; cleanup and the final residual check both found no
  QEMU, runqemu, flutter-auto, or QMP socket.

### Inferences

- Minimal geometry and frame begin are not sufficient to reach the current
  image's Filament command executor or Vulkan present boundary.
- The black QMP result cannot currently be assigned to Flutter parent opacity:
  the same current-image minimal native path emits no command-execution or
  present marker at all.

### Hypotheses

- H1: renderer commands are enqueued but the command-stream worker is not
  draining them in this current-image process.
- H2: the command stream reaches a different worker/dispatcher path whose
  execution is not covered by the current named trace.
- H3: the present trace is unavailable at runtime despite its strings being in
  the binary. The binary check makes this less likely but does not prove the
  command path itself.

### UNKNOWN

- Which thread owns the current command stream and whether it is alive or
  blocked at the p16 boundary.
- Whether the historical visible-cube image used the same worker/dispatcher
  configuration as the current 0208 image.
