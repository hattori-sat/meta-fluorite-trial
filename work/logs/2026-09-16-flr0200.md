## Source integrity clarification

- In `filament-vk`, “empty files” means 74 regular files tracked by the source
  `HEAD` whose blob size is exactly zero bytes. They are intentional
  HEAD-tracked placeholders in that source tree, not newly generated files and
  not evidence that the WSI source was empty.
- Fixed-container verification after the approved restoration reports
  `filament-vk HEAD_ZERO_BYTE_BLOBS=74`, `TRACKED=47877`, and a clean worktree.
  The separate `fluorite-plugins` source reports zero HEAD zero-byte blobs,
  `TRACKED=478`, and a clean worktree after its 256 deleted non-empty HEAD
  files were restored.
- The deterministic recovery rule is: enumerate `git status --porcelain`,
  resolve each tracked deletion against the exact source `HEAD`, restore only
  the explicitly approved paths, require a clean worktree, and only then run
  `git add .` followed by the source commit and official Devtool update. No
  path was inferred from filename patterns and no patch body was hand-written.
