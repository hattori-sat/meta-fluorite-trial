# FLR-0077 — isolate full production shaded boundary

- Ticket: `work/tickets/FLR-0077-isolate-full-production-shaded-boundary.md`
- Status: Done (default indirect-light attachment falsified as sole cause)
- Date: 2026-09-11
- Active work unit: determine whether the missing Scene registration of the
  default indirect light explains the black full-production 3D output.

## Outcome so far

The current evidence separates the problem from the whole 2D/3D composition
path. A self-made native fixture and a production model-only condition still
produce 3D pixels on the current image, while the full production scene stays
black. Static inspection found that the default indirect-light builder result
is discarded and is never installed on the Filament Scene. The HDR path does
install its result.

This is a diagnostic candidate, not yet a product fix. The expected falsifiable
result is that an opt-in Scene attachment changes only the full-production
condition from black to visible shaded geometry.

## Facts

- Existing QMP evidence contains a frame with both the 2D HUD and Sequoia 3D;
  later exact-image reruns show that the stable positive path is the controlled
  model-only/diagnostic condition, not yet the full shaded production path.
- The current rootfs identity and prior controls are recorded in the previous
  FLR-0076 evidence and ticket log.
- In the Mac Devtool source, `setIndirectLight(DefaultIndirectLight*)` calls
  `filament::IndirectLight::Builder::build(*engine)` but does not call
  `scene->setIndirectLight(...)`.
- The HDR loader in the same source destroys the previous scene IBL and calls
  `scene->setIndirectLight(ibl)`.
- The diagnostic source edit was made in the persistent Mac Devtool source
  workspace and committed there as `e2d2444`.
- The edit is opt-in through
  `FLR0026_NATIVE_ATTACH_DEFAULT_INDIRECT_LIGHT`; the default path remains
  unchanged.
- The source diff check completed without output, and the source commit was
  file-scoped to `indirect_light_system.cc`.
- The existing Podman machine and container were reused; no machine, volume,
  source tree, build directory, or TMPDIR was created.

## Inferences

- The stable black result is more specific to the production shaded scene
  boundary than to Flutter/Wayland composition as a whole.
- The discarded default IBL is a stronger next test than another compositor
  patch because the model-only control already proves that the native render
  target can produce visible geometry.

## Hypotheses and falsifiers

1. Default IBL is not registered. Prediction: the opt-in attachment produces
   recognizable production geometry in the same candidate region; the model
   only control remains positive.
2. Explicit light/material/resource state is the real boundary. Falsifier for
   hypothesis 1: the opt-in attachment leaves the full-production candidate
   at zero pixels while frame/present markers remain healthy.
3. The earlier simultaneous HUD/3D frame was a transient diagnostic ordering
   effect. Repeated same-image QMP runs under the new opt-in control will be
   used to distinguish this from a stable rendering fix.
