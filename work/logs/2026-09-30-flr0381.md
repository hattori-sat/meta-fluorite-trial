## Purpose

Compare FLR-0380's all-black current-image QMP frame against the same
low-volume no-light Sequoia launch without `WAYLAND_DEBUG`. Capture QMP while
the Flutter process is alive and preserve the exact SSH/timeout exit status.

### Facts

- FLR-0378 on rootfs `949921c…` showed a black/achromatic Sequoia silhouette on
  a gray field with no HUD. Its high-volume stage trace generated 143,284
  repeated asset-ready records; the raw guest log was lost after session end.
- FLR-0380 (local predecessor commit `fbed630`, not pushed) held the same
  candidate and no-light scene profile, recorded a child surface
  attach/damage/commit, first present return `0`, no second return, and an
  all-black QMP frame identical to pre-Flutter. Its exit status was not saved.
- FLR-0207/0214/0215/0219 and FLR-0339/0341/0342/0343/0350/0365/0366/0374
  already cover older-candidate SHM/compositor and present-wait investigations.
  This ticket will not repeat them.
- Flutter was manually invoked as `agl-driver` on the guest for both runs; the
  existing Mini QEMU harness was reused. No persistent launch/capture script,
  source, patch, or image was changed.
- Run 0001 ended at bounded status `124`. The still was gray, but capture-time
  liveness is UNKNOWN; the later eight-frame capture was after Flutter exited
  and was black. Do not use run 0001 as proof of live rendering.
- Run 0002 repeated the same candidate/profile. Strict SSH checks confirmed
  Flutter alive immediately before the QMP still and after its eight-frame
  video. The full frame and all eight frames were uniform RGB `(224,224,224)`;
  vehicle and HUD ROIs had zero edges/chromatic pixels. Two present calls
  returned `0`, a third had no captured return, and the bounded status was
  `124`.
- Both QMP sessions were stopped through their owned sockets; independent
  teardown checks found no remaining QEMU/runqemu/flutter-auto process, QMP
  socket, or occupied forwarded port. Run 0001's bounded kernel/core check was
  clean for selected Oops/OOM/segfault signals; run 0002's kernel/core state is
  UNKNOWN.
- QMP review media is linked in
  [the evidence manifest](../evidence/FLR-0381-runtime.md). Raw PPMs and guest
  logs stayed on Mini; no disk image or raw PPM was copied to Mac.

### Inferences

- The highest-value comparison is a direct pair to FLR-0380, changing only
  `WAYLAND_DEBUG`; FLR-0378 is a visual reference, not a clean single-factor
  control because its logging profile differed.
- If the frame changes, this run proves correlation only. The final product
  criterion remains same-frame colored production Sequoia plus 2D HUD.
- Both run stills were gray, but only run 0002 passed the live-capture checks;
  there is one verified live gray capture, not two independent live repeats.
  It differs from FLR-0380's black QMP result but does not establish
  `WAYLAND_DEBUG` as the cause. A gray no-light frame cannot diagnose
  production lighting or texture appearance.
- Successful model/material and present markers prove progress through setup
  and present boundaries only; QMP pixels prove neither the Sequoia nor HUD
  was visible in the live captured frame.

### Hypotheses

1. `WAYLAND_DEBUG` affects timing/surface behavior; prediction: a different
   QMP image or present/exit sequence with that variable absent. The live gray
   result is consistent with a difference but does not establish causality.
2. The render/present failure is independent; prediction: all-black QMP and
   unmatched present recur. The live gray result did not match the all-black
   prediction; the unmatched return was on the third present call.
3. The run is variable or the capture window misses useful output; prediction:
   inconsistent pixels/process/marker evidence, requiring UNKNOWN rather than
   a causal claim. Run 0001 still liveness was UNKNOWN; run 0002 had a stable
   live gray still/video, so run variability is not ruled out.

### UNKNOWN

- Whether `WAYLAND_DEBUG` caused or merely correlates with the FLR-0380 black
  frame.
- Why the no-light live frame is uniformly gray despite model/material setup
  and successful present returns.
- Whether the unmatched third queue-present call would return after the
  45-second bound.
- Whether production Sequoia and 2D HUD can be shown together in one current
  QMP frame.
- Run 0002 kernel/Oops/coredump state; not separately collected.
