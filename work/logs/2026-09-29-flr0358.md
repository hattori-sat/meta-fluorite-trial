### 4W1H and process analysis

| Cut | Evidence |
| --- | --- |
| What | Handoff preflight could not reach the authoritative effective metadata query. |
| When | Mini build/source checkouts are separate; the first receiver mutation has not occurred. |
| Where | `reuse-mini-build-receiver.sh`, OE-init selection stage before `bitbake -e` and before `git fetch`. |
| Who | The handoff helper owns source selection; the active build config identifies the required template. No individual attribution. |
| How | The helper searched only ancestors of `BUILD_DIR`; the successful AGL source checkout is elsewhere under the fixed source roots. |

Why-why, after the first process mismatch:

1. The metadata query did not run because OE initialization returned nonzero.
2. That init script was the standalone Poky tree; its template directory did
   not match the build's persisted selection.
3. The helper assumed the source checkout was an ancestor of the build.
4. Its integration fixture placed source and build together and did not model
   the actual split layout or bind source choice to `TEMPLATECONF`.
5. FLR-0109's correction remained a manual operational note rather than an
   executable helper contract, so the same failure signature recurred.

The process problem is therefore source-resolution and regression coverage,
not BitBake parsing, receiver Git state, or a product/3D defect. The countermeasure
is deterministic candidate-to-template binding plus tests that fail before any
receiver mutation.
