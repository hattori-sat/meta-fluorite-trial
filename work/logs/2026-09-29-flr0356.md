## Iteration 2 — red/green staging contract

### Facts

- Added `test_all_fixed_guest_commands_are_staged_before_qemu_start` first and
  ran the suite against the unmodified runner. The run was RED as intended:
  28 tests, one new failure (`runner has no static command inventory`), and 27
  pre-existing tests passed.
- The runner now defines one eleven-file `runtime_command_files` array. Its
  embedded static check parses this array instead of keeping a second Python
  list, rejects missing/empty/duplicate inventory entries, ensures every fixed
  `guest_run` callsite is represented, and verifies each source is readable,
  one-line, within the serial byte limit, and accepted by `sh -n`.
- Before target preflight/side effects, the runner verifies source readability.
  After creating the evidence parent it copies the complete array there before
  QEMU `start`; after launch it copies those exact staged inputs into the QEMU
  run directory. `guest_run` retains its run-directory then parent lookup.
- The static fresh-ID sample is now `flr0356-0001`; the consumed ID remains
  `flr0350-0001` and the shared validator policy is unchanged.
- The green run passed all 28 focused tests. Bash syntax and the runner's
  `--check` also passed: 11 commands, exact diagnostic profile, static
  `QEMU_NOT_STARTED`, and run-ID reuse rejection.
- No Mini transfer, BitBake/Devtool/build, QEMU launch, or product/image
  change has occurred in FLR-0356.

### Inferences

- The exact source omission from FLR-0355 is now directly represented as a
  regression, and the runtime staging copy precedes the QEMU start invocation.
- The new static check catches future fixed callsites missing from the single
  array and catches missing/unreadable command source files before any target
  state is touched.
- This only validates host-side command preparation. Guest `stat`/FD identity,
  GDB/GO, renderer state, and visible 3D remain unknown until one Mini run.
