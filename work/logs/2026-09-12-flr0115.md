## Iteration 2 — preserve existing WORKDIR while refreshing archive identity (2026-09-12)

### Facts

- The first implementation placed the lock in `do_patch`, but the existing
  WORKDIR still contained the old `PUB_CACHE_ARCHIVE` marker. The standard
  archive task checks that marker before recomputing its identity, so a plain
  forced archive task could reuse the pre-fix archive.
- Deleting the marker under the protected build `tmp` tree was rejected by
  the project safety boundary and was not performed.

### Decision

- Keep the existing lock and cache. After installing the lock in `do_patch`,
  overwrite only the exact generated marker with a non-existent refresh value.
  `meta-flutter` then recomputes the archive name from the lock-bearing source
  tree; an existing matching archive is reused and a changed identity creates
  only the required new archive.

### Check

- The focused lock-order test now also requires the marker-refresh behavior.
- The revised recipe, bundle, archive task, and offline compile are pending.
